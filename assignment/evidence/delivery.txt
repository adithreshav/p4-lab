Command: sh cat logs/h2.txt logs/h3.txt
Output:
Listening on h2-eth0...
Received (tunnelled, dst_id=2, hop_limit=6) from 10.84.0.1 to 10.84.0.2, TTL 64: 'to h2'
Listening on h3-eth0...
Received (tunnelled, dst_id=3, hop_limit=6) from 10.84.0.1 to 10.84.0.3, TTL 64: 'to h3'

Short explanation: Hop limit is 6 because each switch on the tunnel path checks the hop limit and decrements it by 1. Since it goes to s1 and s2 it decrements by 2. The TTL is still 64 because the tunneled packets go through myTunnel_exact which only sets the output port.

Command: h1 ping -c 2 h3
Output:
PING 10.84.0.3 (10.84.0.3) 56(84) bytes of data.
64 bytes from 10.84.0.3: icmp_seq=1 ttl=62 time=4.86 ms
64 bytes from 10.84.0.3: icmp_seq=2 ttl=62 time=8.09 ms

Short explanation: For ping, the TTL decrements because a ping has no tunnel header and the switches will use ipv4_lpm which has actions = { ipv4_forward; drop; } that decrements the TTL. h3 will send it with 64, going through s2 and s1 will decrement it by 2.
